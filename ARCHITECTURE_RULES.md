# ARCHITECTURE RULES

These rules exist to prevent the rebuild from recreating the architectural problems of the legacy system.

Read before making major changes.

---

# Core Philosophy

The rebuild prioritizes:

- workflow clarity
- typed contracts
- modularity
- frontend visual fidelity
- restrained UX
- operational continuity
- maintainability

The rebuild intentionally avoids:
- fake AI orchestration complexity
- hidden synchronization
- giant mutable state
- distributed-system theater

---

# NEVER DO THESE

## Frontend

Do NOT introduce:
- giant global mutable state
- mega context providers
- frontend-owned backend truth
- hidden synchronization
- dashboard overload
- operational spam surfaces
- generic SaaS dashboard patterns
- equal-weight visual density

---

## Backend

Do NOT introduce:
- fake agent orchestration layers
- websocket/event infrastructure prematurely
- distributed workflow engines
- hidden persistence coupling
- giant god services
- implicit workflow mutations

---

## Product UX

Do NOT:
- overexpose internal workflow state
- overload the UI with widgets
- replace cinematic minimalism with dashboard density
- make the assistant rail operationally noisy
- add fake AI intelligence theater

---

# ALWAYS PRESERVE

## Frontend

Preserve:
- premium dark command-center feel
- restrained spacing
- sparse composition
- dominant focal hierarchy
- emotional parity with deployed product
- visual calmness
- strong typography rhythm

---

## Backend

Preserve:
- typed APIs
- modular workflows
- explicit workflow state
- isolated persistence boundaries
- workspace scoping
- deterministic execution where possible

---

# Workflow Rules

Workflows should:
- be explicit
- be typed
- be traceable
- avoid hidden side effects
- avoid implicit state synchronization

Workflow lineage must stay visible.

---

# Assistant Rail Rules

The assistant rail should:
- feel ambient
- feel lightweight
- support workflows
- preserve breathing room

The assistant rail should NOT:
- become a fake orchestration debugger
- expose excessive operational metadata
- become a giant chat-state system

---

# Frontend Visual Rules

The original deployed product is the visual source of truth.

Prioritize:
- restraint
- spacing
- compositional confidence
- sparse operational surfaces
- emotional realism

Avoid:
- over-designed dashboards
- feature overload
- excessive cards
- cluttered layouts

---

# Rebuild Intent

This rebuild is intentionally:
- cleaner architecturally
- simpler operationally
- visually faithful
- workflow-oriented

It is NOT:
- a distributed AI-agent platform
- a realtime orchestration system
- a websocket-heavy application
- an autonomous multi-agent framework

---

# Before Major Changes

Ask:
1. Does this preserve workflow clarity?
2. Does this preserve visual restraint?
3. Does this introduce hidden coupling?
4. Does this recreate legacy chaos?
5. Does this improve product feel?

If not, reconsider the change.
